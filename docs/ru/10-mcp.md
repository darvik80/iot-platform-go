# MCP — управление устройствами через LLM

MCP (Model Context Protocol) позволяет LLM напрямую работать с устройствами на платформе: читать телеметрию, вызывать RPC, менять атрибуты. Протокол — **Streamable HTTP**, встроен в платформу на эндпоинт `/mcp`. Отдельного процесса, контейнера или порта нет.

```
http://<platform-host>:8080/mcp
```

## Как это работает

LLM-клиент (Cursor, Claude Desktop, собственный агент) подключается к `/mcp` и вызывает инструменты. Платформа транслирует вызовы в MQTT-команды устройствам и возвращает результат.

```
LLM → MCP tool call → платформа → MQTT downlink → устройство
                  ← JSON результат ← платформа ← MQTT uplink ←
```

## Инструменты

### Чтение

| Инструмент | Что возвращает |
|-----------|---------------|
| `overview` | Счётчики онлайн/офлайн, статус MQTT-брокера, число подключённых клиентов |
| `list_devices` | Список устройств с фильтрацией по продукту, статусу (`online`/`offline`), текстовому запросу |
| `get_device` | Полная карточка устройства: телеметрия, атрибуты, схема продукта, последние события |
| `list_products` | Все продукты с RPC-методами и схемами атрибутов |
| `get_product` | Один продукт с определениями RPC-методов (имя, параметры) |
| `list_device_methods` | RPC-методы продукта конкретного устройства (всегда включает встроенный `rpc-list`) |
| `get_telemetry` | Последние сэмплы телеметрии устройства |
| `get_attributes` | Reported и desired атрибуты устройства |

### Запись

| Инструмент | Что делает |
|-----------|-----------|
| `invoke_rpc` | Вызов RPC-метода на устройстве (через MQTT downlink). Указать `method` и `params` |
| `reboot_device` | Быстрая перезагрузка устройства (шорткат для `invoke_rpc` с `method=reboot`) |
| `set_desired_attributes` | Отправить desired-атрибуты на устройство |

Все инструменты записи требуют роль **operator** или **admin** у пользователя токена.

### Идентификация устройства

Любой инструмент принимает идентификатор устройства двумя способами:
- `id` — платформенный числовой ID
- `product_id` + `device_id` — строковая пара идентичности

Достаточно указать один вариант.

## Подключение Cursor

1. Открыть дашборд → **Settings** → создать API-токен (напр. имя `mcp`)
2. Скопировать `cip_…` — он показывается один раз
3. Конфигурация Cursor (Settings → MCP):

```json
{
  "mcpServers": {
    "cogitor-iot": {
      "url": "http://192.168.1.100:8080/mcp",
      "headers": {
        "Authorization": "Bearer cip_…"
      }
    }
  }
}
```

После этого в чате Cursor доступны инструменты `cogitor-iot.*`.

## Получение API-токена через API

Если нужно автоматизировать создание токена:

```bash
# 1. Login JWT (короткоживущий)
JWT=$(curl -s -X POST http://192.168.1.100:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin","password":"admin"}' | jq -r .token)

# 2. Создать долгоживущий API-токен
curl -s -X POST http://192.168.1.100:8080/api/v1/me/tokens \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{"name":"mcp"}'
# → { "token": "cip_…", "token_prefix": "cip_…", … }
```

## Пример: перезагрузка ESP32

Сценарий: нужно перезагрузить устройство `esp32-cam` / `cam-001`.

### 1. Найти устройство

Вызов `list_devices`:
```json
{ "query": "esp32" }
```

### 2. Проверить доступные методы

Вызов `list_device_methods`:
```json
{ "product_id": "esp32-cam", "device_id": "cam-001" }
```

В ответе — список методов из схемы продукта. Ищем `reboot` с параметром `delayMs`.

### 3. Перезагрузить

Через `reboot_device` (шорткат):
```json
{
  "product_id": "esp32-cam",
  "device_id": "cam-001",
  "delay_ms": 500
}
```

Или через `invoke_rpc` (универсальный способ):
```json
{
  "product_id": "esp32-cam",
  "device_id": "cam-001",
  "method": "reboot",
  "params": { "delayMs": 500 }
}
```

Платформа публикует MQTT downlink RPC. Устройство подтверждает и перезагружается.

Пример промпта для LLM:

> Перезагрузи устройство esp32-cam / cam-001 с задержкой 500мс через MCP-инструменты Cogitor IoT.

## Развёртывание

MCP — часть бинарника `/platform`. Без дополнительного Docker-сервиса, порта или переменной окружения. Эндпоинт `/mcp` доступен на том же порту, что и HTTP API (`HTTP_ADDR`, по умолчанию `:8080`).
